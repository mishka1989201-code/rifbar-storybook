# Modal

The dialog surface of a form pop-up: header with an icon, title and close button, body sections separated by lines, footer with actions.
Implements the Figma frame [`Pop-up warehouse`](https://www.figma.com/design/4Q7E8IQ07a9xFiNVBfmo4M/ERP-System-v-1.1--Mockups----Rifbar-2023?node-id=7058-30262) (`Property 1` Desktop / Mobile). It is composed of [IconButton](?path=/docs/atoms-iconbutton--docs) (close), [Icon](?path=/docs/atoms-icon--docs), [InputField](?path=/docs/atoms-inputfield--docs) and [Button](?path=/docs/atoms-button--docs).

It draws **only the dialog**. The overlay (`--shadow-backdrop`-style dim), centring, scroll lock, focus trap and `Esc` handling are up to the page.

## When to use

- ✅ Short forms and confirmations that interrupt the flow: create / edit a warehouse, a category, a user.

## When NOT to use

- ❌ Long forms with many steps — use a page. Passive messages — use [Notification](?path=/docs/molecules-notification--docs).

## Figma notes

- Figma `Add Product Modal` ([node 682:287127](https://www.figma.com/design/4Q7E8IQ07a9xFiNVBfmo4M/%F0%9F%93%B1-ERP-System-v-1.1--Mockups----Rifbar-2023%F0%9F%93%B1?node-id=682-287127)) is this same dialog (450px, `Plus` icon, h4 title, one `Filter` field, Close / Save) — no new component; see the `AddEmployee` story. The frame name says “Product” but the content is about adding an employee to a warehouse.
- Figma shows only the surface, no overlay, no shadow and no open / close animation; none were added.
- Figma has a bottom line on the last body section **and** a top line on the footer (two 1px lines in a row); kept as drawn.
- The mobile footer buttons are 12px high-padded (`12 16`), which does not match any `Button` size (small / medium 8, big 16); `Modal` overrides the padding for buttons inside the mobile footer.
- The desktop title is `nowrap` in Figma; in code it wraps (`overflow-wrap: anywhere`), the close button keeps its 40px.
- The title icon is aligned to the first line of the title with a 4px top padding (as in Figma `Add Product Modal`, where the title wraps); before this it was centered against the whole title.
- Icon: the Figma `Plus` (dark rounded square) matches the existing `plus-box` 24px.
- Not designed, AI-defined: a modal without icon or without footer, the invalid field state (from `InputField`), focus ring on the close button (from `IconButton`), the modal at narrow widths (`width: 100%` with the Figma widths as `max-width`). Dark theme not designed — light values are used.
- Figma notes on the `InputField`: Static = Stroke Input border, Grey Dark placeholder — the atom already does this.

## Code example

```tsx
import { Button, FilterField, InputField, Modal, ModalField, ModalSection } from 'rifbar-ds';

<Modal
  title="Create warehouse"
  onClose={close}
  actions={
    <>
      <Button variant="light" iconLeft="xmark" onClick={close}>Close</Button>
      <Button variant="dark" iconLeft="tick" onClick={save}>Accept</Button>
    </>
  }
>
  <ModalSection>
    <ModalField label="Warehouse name" htmlFor="name">
      <InputField id="name" placeholder="Enter the name of the warehouse" />
    </ModalField>
  </ModalSection>
  <ModalSection>
    <ModalField label="Manager" htmlFor="manager">
      <FilterField id="manager" placeholder="Choose a warehouse manager" />
    </ModalField>
  </ModalSection>
</Modal>
```

## Accessibility

- `role="dialog"` labelled by the title (`aria-labelledby`). Add `aria-modal="true"`, a focus trap, focus return and `Esc` to close in the page that opens it.
- `ModalField` renders a real `<label>`; pass `htmlFor` with the control `id`.
- The close button is a 40px native button with `aria-label` “Close” — below the 44px touch target, kept as designed; fields are 32px high.
- Secondary Grey `#A7A4B7` stroke of the close button on white is below 3:1 contrast — kept as designed.
